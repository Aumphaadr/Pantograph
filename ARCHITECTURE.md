# Пантограф — устройство

`SPEC.md` отвечает на вопрос «что делаем и в каком порядке». Этот документ —
«как оно связано»: типы, границы, кто с кем говорит и почему именно так.

## 0. Что показал референс

Тонкоштриховая иконка с пробного референса — 22×20 пикселей. Карта плотности
(`#` — заливка, `+` — краевой пиксель), фон взят пипеткой с сайдбара:

```
............+++...............
...........+###+..++..........
..........+#+++#+.++..........
.........+#+...+#+++..........
........+#+.....++++..........
.......+#+.......++++.........
......+#+..........+++........
....++#+............+++.......
...+##+.............++#+......
```

**34 полных пикселя против 148 краевых.** 81% иконки живёт в антиалиасинге,
штрих шириной около одного пикселя. Абсолютные числа зависят от того, какой фон
взят пипеткой: сдвиг опоры на десяток единиц двигает счёт на два-три пикселя.
Устойчива именно доля — на ней и держится вывод. Проверка: `tests/browser.html`. Отсюда главный вывод, который правит
этап 1 спеки:

> Порог применяется **после** апскейла, а не до. Субпиксельное положение края
> закодировано в градиенте; жёсткий порог по исходному разрешению эту
> информацию выбрасывает и рвёт штрих на куски.

Поэтому основной промежуточный тип конвейера — **мягкая маска** `Float32Array`
со значениями 0..1, а не битовая карта. Бинаризация — предпоследний шаг перед
трассировкой, а не первый шаг после кропа.

## 1. Четыре инварианта

Правила, которые держат проект от гниения. Нарушение любого из них — повод
откатить правку, а не «поправим потом».

1. **`Shape` всегда в crop-пространстве.** Трассировщик делит результат на
   коэффициент апскейла сразу; наружу апскейл не протекает никогда.
2. **Переворот Y происходит ровно в одном месте** — `glyphs/metrics.toGlyphSpace()`.
   Никакой другой модуль про направление оси не знает.
3. **SVG рождается только в `export/svg`.** Внутри системы путей-строк нет.
4. **Экранные координаты знает только `ui/viewport`.** Ни один модуль логики
   не видит ни зума, ни панорамы, ни CSS-пикселей.

## 2. Пространства координат

| Пространство | Начало | Ось Y | Единицы | Кто в нём живёт |
|---|---|---|---|---|
| image | левый верх картинки | вниз | px исходника | прямоугольник кропа |
| **crop** | левый верх кропа | вниз | px исходника | мягкая маска, **Shape**, направляющие, компоненты |
| mask | левый верх кропа | вниз | px × k | только внутри `prep` и `trace` |
| glyph | базовая линия × левый край | **вверх** | units, upm 1000 | `Glyph` |
| screen | канва | вниз | css px | только `ui/viewport` |

Переходов между пространствами всего три, и у каждого один хозяин:
`prep/mask.upscale` (crop → mask), `trace.trace` (mask → crop, делит на k),
`glyphs/metrics.toGlyphSpace` (crop → glyph, переворот Y).

## 3. Типы

```js
// core/path.js — на этом говорят все
Pt      = { x, y }
Node    = { p: Pt, in: Pt|null, out: Pt|null, type: 'smooth'|'corner' }
Contour = { closed: boolean, nodes: Node[] }
Shape   = { contours: Contour[] }

// prep/mask.js — единственный растровый тип
Mask    = { w, h, data: Float32Array }   // 0..1

// glyphs/
Component = { id, bbox, mask: Mask }      // мягкая маска, обрезанная по метке
Group     = { id, componentIds: [], bbox }
Glyph     = { codepoint, shape: Shape, advance, lsb, source: Group }
Guides    = { baseline, xHeight, capHeight, descender }   // Y в crop-пространстве
```

Рычаги `in`/`out` — **абсолютные точки**, не смещения. Так проще попадание
курсором и перетаскивание; общий `transform(shape, matrix)` двигает все три
точки узла, и разница между абсолютными и относительными перестаёт значить.

Направление обхода: внешние контуры по часовой, дырки против (в Y-вниз).
`core/path.orient(shape)` приводит к норме и вызывается после трассировки
и после каждой операции редактора, способной развернуть контур. Без этого
дырки в «О» и «Ф» зальются в `.otf`.

Один растровый тип `Mask` сквозь весь препроцесс важнее, чем кажется: порог —
это тоже просто `Mask → Mask`, поэтому шаги свободно переставляются и
тестируются поодиночке.

## 4. Конвейер и граница владения

```
                     ×k живёт только здесь
                    ┌───────────────────────┐
кроп → расстояние → апскейл → порог+морф → трассировка ║ редактор → экспорт
       по цвету     Lanczos                            ║
       Mask 0..1    Mask ×k     Mask 0|1        Shape  ║ Shape
                                                   ║
       ←── всё это чистая функция параметров ───→  ║  ←─ принадлежит человеку
```

Слева от стены — **производное состояние**. Любой ползунок можно двигать
сколько угодно: всё пересчитывается молча, терять нечего.

Справа — **отчуждённое**. Как только человек тронул узел, `Shape` копируется в
редактор и становится его собственностью; параметры замораживаются и
показываются только для чтения. Кнопка «перетрассировать» есть, но требует
подтверждения и выбрасывает правки.

**Почему не переносить правки на новую трассировку.** Соблазн очевиден:
пересчитал с другим порогом, наложил сохранённые правки сверху. Но
идентичность узла не переживает перетрассировку — другой порог даёт другое
количество узлов в других местах. Любое сопоставление будет эвристикой,
которая молча испортит работу. Честная стена лучше умного вранья.

Смягчение: снимок параметров хранится вместе с отчуждённым `Shape`, поэтому
«перетрассировать с теми же настройками и начать правку заново» — одна кнопка,
а не археология.

## 4а-бис. Углы — по упрощённому, подгонка — по плотному

Урок, купленный на буквах. Сначала конвейер упрощал изолинию (RDP), находил
углы и подгонял кривые ПО УПРОЩЁННОМУ многоугольнику. Это тихое враньё в
геометрии: RDP выкидывает все точки прямой, между двумя её концами не остаётся
ни одного свидетеля, а `maxError` Шнайдера меряет отклонение только по
внутренним точкам пробега. Сегмент без свидетелей «проходит» проверку с
нулевой ошибкой при ЛЮБОЙ форме — и с чужими касательными (гладкий шов на
нераспознанном углу) прямые стороны букв уходили дугами в пустоту, а рычаги
упирались в зажим 1.4 хорды.

Теперь роли разделены. Упрощённый многоугольник — измерительный: на нём ищутся
и уточняются углы (по плотному их не измерить — шум сетки забивает поворот).
Подгонка же идёт по ПЛОТНОЙ изолинии, в которую воткнуты найденные вершины
(`anchorCorners`): точки в радиусе фаски вокруг вершины гасятся, чтобы пиксели
срезанного угла не тянули кривую прочь. У каждого сегмента сотни свидетелей,
и ошибка меряется по-настоящему. Касательные на швах берутся окном в пару
пикселей маски, а не по соседней точке: по соседней они дрожат квантованием
на сорок пять градусов.

То же в осевой линии, с поправкой: срединная ось прямого угла — фаска в 45°
длиной с толщину штриха (скелет идёт по биссектрисе, в вершину ему не попасть),
поэтому там фаска срезается и окно поиска углов берётся от ТОЛЩИНЫ.

## 4а-тер. Выравнивание: вернуть букве замысел

Растровая буква не бывает идеальной: кромка гуляет на полпикселя, прямой
угол — на пару градусов, круглая точка чуть овальна. Подгонка честно повторяет
этот шум, но человек-то рисовал прямую. `trace/regularize.js` возвращает
замысел, и порог всюду один — допуск подгонки («Точность»): форма не
выдумывается, из НЕОТЛИЧИМЫХ кандидатов выбирается самый правильный.

Канон хороших контуров, по которому пересобираются гладкие пробеги:
узлы стоят НА ЭКСТРЕМУМАХ по x и y, рычаги в экстремумах строго осевые,
кусок кривой не длиннее квадранта. Это не вкусовщина: Шнайдер законно
укладывает полуокружность в одну кубику с рычагами поперёк хорды (ошибка
~0.3 px — допуск проходит), но править такое невозможно. Гладкое кольцо без
углов режется от гарантированной макушки. Все касательные при пересборке —
вперёд по ходу: endTangent с отрицательным шагом уже смотрит назад, и
развернув его второй раз, получаешь конец, торчащий наружу, — Шнайдер тогда
дробит даже идеальную прямую. Рычаги в паре градусов от кратных 15°
доворачиваются точно. Последним словом — честность типов: узел с изломом
рычагов больше 8° объявляется угловым, иначе человек тянет рычаг угловатого
на вид узла, а данные говорят «гладкий», и зеркалирование срабатывает
«само». Любая замена принимается только когда пересобранное неотличимо
от исходного в допуске.

Согласование (glyphs/harmonize.js) — то, что в букве задумано одинаковым,
делается одинаковым точно. Симметрия в три эшелона: свёртка МАСКИ по гейту
несовпадения половин (ось — центр масс; гейт 7% выбран по замеру листа) →
трассировка симметричных данных → зеркальная ПЕРЕСБОРКА контура: разрез по
оси, худшая сторона — зеркало лучшей; чаши «Ф» — худшая заменяется зеркалом
лучшей целиком. Парное усреднение узлов не работает: даже на свёрнутой маске
стороны трассируются с разным СТРОЕНИЕМ узлов. Перед заменой стороны
сверяются выборками с порогом в долю размера — симметрия наводится, но не
выдумывается; работа на клоне, неудача любой оси откатывается целиком.
Толщины штрихов выравниваются по всему листу: пары осевых граней напротив —
штрихи, группы близких толщин идут к своей медиане, сдвиг грани ограничен.

Лестница выравнивания: контур, неотличимый от прямоугольника или эллипса, —
им самим (многоугольник исключён намеренно: внешний контур буквы и есть
многоугольник, приводить его — терять букву; и решает флаг fits у detect —
он ВСЕГДА возвращает «наименее плохой» примитив, и без проверки флага «Н»
приводилась к кругу целиком) → пробег, неотличимый от прямой ХОРДЫ, —
прямая под любым углом (диагональ «И» без этого оставалась цепочкой пологих
кривых) → пересборка по экстремумам с осевыми рычагами → сегмент,
неотличимый от своей хорды, — прямая → прямая в паре градусов от осевой —
осевая (горизонтали правят y, вертикали правят x; гладкий стык прямой с
кривой сохраняет G1) → узел между коллинеарными прямыми схлопывается →
ПРОБНОЕ УДАЛЕНИЕ: гладкий узел, без которого перефит двух его сегментов
одной кубикой неотличим от прежних, — лишний (угловые и экстремумы
защищены) → рычаги к сетке 15° → честность типов.

Работает только в шрифтовом маршруте (галка «Выравнивание»): иконка остаётся
при философии «предлагает, а не применяет».

Рядом — три угловые починки той же серии: дубли углов на скруглённых плечах
склеиваются, и отличитель дубля от пазухи «И» — прогиб дуги между углами
(у плеча она прижата к хорде, у пазухи ныряет вглубь щели); вершина угла
двигается в пересечение боков, только когда ОБА бока — настоящие прямые
(хорда дуги, продолженная за дугу, промахивается — у полукольца «й» рос рог);
свидетели плеча гасятся в окне угла, а не только в фаске, — иначе узлы
толпились по два-три на угол.

## 4а. Трассировка: изолиния, а не обводка пикселей

Обычный трассировщик обводит границы пиксельных областей растра и потом
сглаживает лесенку. Здесь берётся **изолиния непрерывного поля** маршевыми
квадратами с линейной интерполяцией по рёбрам ячеек: положение края между двумя
пикселями закодировано в их дробных значениях и читается напрямую.

Дальше — упрощение, поиск углов по отклонению от прямой, подгонка кубических
кривых по Шнайдеру (наименьшие квадраты с хордовой параметризацией, уточнение
Ньютоном, деление в точке наибольшей ошибки).

Три вещи, которые выяснились только на настоящих данных:

- **Касательную на концах дуги нельзя брать хордой до соседа.** Ошибка первого
  порядка (пара процентов) не даёт кривой лечь ни при каком допуске, и та
  начинает без нужды дробиться. Берётся производная параболы через три точки
  с неравномерным шагом.
- **Рычаги надо ограничивать.** На штрихе толщиной в пиксель касательные почти
  параллельны, система вырождается, и решение уходит в бесконечность: узлы
  остаются на месте, а рычаги улетают за пределы кропа — кривая делает петлю
  через полкартинки. Длина рычага зажата двумя хордами.
- **Радиус склейки кандидатов в углы — не то же, что окно измерения.** Окну
  надо быть широким, чтобы поворот мерился устойчиво; склейке узкой, чтобы не
  съесть соседний настоящий угол. С общим радиусом у буквы «И» восемь углов
  схлопывались в шесть, подгонка перемахивала через пазухи и заливала их:
  площадь контура выходила в 1.67 раза больше самой буквы.
- **Рычаг не длиннее 1.4 хорды.** У четверти окружности их отношение около 0.39,
  у половины 0.67; всё, что заметно длиннее хорды, — признак вырожденной
  системы, а не формы. Прежний двойной запас пропускал рычаг в 80 при хорде 49,
  и почти прямой участок уходил в сторону. Значение подобрано замером: до 1.4
  буква держится, при 1.6 ломается снова, а экономия узлов между ними —
  единицы процентов.
- **Угол ставится в настоящую вершину, а не на ступеньку растра.** Изолиния
  идёт по лесенке пикселей, поэтому узел угла садится на срез, и угол выходит
  «рубленым» примерно на пиксель — это хорошо видно на М, Н, Т, Щ. Вершина
  находится пересечением прямых, проложенных ортогональной регрессией по ровным
  участкам с обеих сторон; сами ступеньки возле угла в расчёт не берутся.
  Отдельно срезается фаска — короткая ступенька между двумя кандидатами
  в углы, с двумя предохранителями, чтобы не съесть настоящую короткую сторону.
- **Контур без углов режется по крайним точкам.** Иначе окружность подгоняется
  от случайного шва двумя узлами в произвольных местах вместо четырёх там, где
  их поставил бы человек. На гладком разрезе обе стороны берут одну прямую
  с разными знаками — только так узел выходит по-настоящему гладким, а не
  просто помеченным гладким.

**Цвет штриха угадывается срединным, а не самым дальним от фона.** Самый
дальний пиксель — это блик. На кропе в полсотни пикселей разница незаметна,
а на мастере в 1254 догадка уезжала в почти белый (255,245,81 вместо золотого),
маска ловила полпроцента картинки, и иконка не обводилась вовсе. Теперь берётся
медиана по каналам среди пикселей, удалённых от фона не меньше чем на шесть
десятых от УСТОЙЧИВОГО максимума (сотой сверху, а не абсолютного): одинокий
пересвеченный пиксель не задаёт шкалу. Считается гистограммами, без сортировки.

**Умолчания и пределы ползунков соразмерны кропу.** Единицы остаются
абсолютными — пиксели исходника предсказуемы, — но начальное значение и границы
подгоняются под размер: длины линейно, площади в квадрате, от базы в 48 px.
Пределы тоже, и это не мелочь: ползунок «окно угла» с потолком в четыре пикселя
на мастере бесполезен, там нужно тридцать. Подгонка срабатывает только пока
человек не трогал ползунки сам.

Без этого крупные исходники непригодны: у логотипа в 1254 px выходило 2633 узла
и 191 контур, по секунде на иконку. С подгонкой тот же геймпад даёт 25 узлов
в 48 px и 39 в 1254 — как и должно быть у одной и той же фигуры.

**Все длины наружу выражены в пикселях ИСХОДНИКА**, а не увеличенной маски —
и упрощение, и точность подгонки, и порог выброса мусора, и окно поиска угла.
Иначе ползунок увеличения молча менял бы плотность узлов: допуск в 0.55 пикселя
маски при ×6 — это 0.09 пикселя исходника, вшестеро строже, чем при ×1.
На наборе icon-crops это стоило примерно двукратного перебора узлов: щит
выходил на 153 узла там, где хватает 41.

**Поиск угла меряет поворот по окну, а не по соседним вершинам.** Маршевые
квадраты срезают прямой угол фаской в полпикселя, и по соседям он выглядит как
два поворота по 45°, то есть не угол вовсе. Раньше фаску случайно съедало
упрощение — распознавание углов зависело от настройки упрощения, чего быть не
должно. Из окна следует подавление немаксимумов: кандидаты, стоящие ближе окна
друг к другу, — это один угол, и остаётся самый крутой. Сравнивать каждого
с соседом нельзя: на квадрате все повороты равны, и при таком сравнении все
четверо уступают предшественнику по кругу, не оставляя ни одного.

**Увеличение зажато по абсолютному размеру маски** (`capScale`). Коэффициент
берётся от высоты буквы или ползунком, но кроп бывает и большим: картинка
1254×1254 при ×6 дала бы маску 7524×7524 — четверть гигабайта на один массив.
Крупному исходнику увеличение и не нужно, у него край и так разрешён.

### Симметризация

Между увеличением и порогом встаёт ещё один шаг `Mask → Mask`. Симметризуется
**маска, а не кривые**: пары узлов на двух половинах не совпадают — слева их
может быть пять, справа семь, — и всякое сопоставление окажется догадкой.
Отражённое и сложенное поле даёт симметричный контур по построению, вместе
с узлами и рычагами.

До порога, а не после: складывать надо полутона, иначе теряется субпиксельный
край. Ось ищется сама — грубый проход вокруг центра тяжести, потом сужение
шага; отражение с дробной осью считается линейной интерполяцией.

**Оценку симметрии нельзя брать как расхождение на оси.** У штриха толщиной
в пиксель даже полпикселя перекоса дают огромную долю, и симметричная фигура
выходит «на 24% несимметричным» — число, которое вводит в заблуждение.
Поэтому лучшая ось сравнивается с заведомо неверной, сдвинутой на седьмую
часть ширины: если лучшая заметно лучше, ось есть. По этой мере симметричная
иконка даёт ~75%, несимметричная — ~35%, и видно сразу, кому она повредит.

Только на иконочном маршруте: строку текста симметризовать нечего.

### Приведение к примитивам

Из растра круг выходит картошкой с лишними узлами, хотя по смыслу это четыре
точки с симметричными рычагами и одной кривизной. `core/primitives` сверяет
контур с кругом, эллипсом, прямоугольником, скруглённым прямоугольником и
многоугольником — от простого к сложному, побеждает первый уложившийся в допуск.
Иначе круг всякий раз признавался бы эллипсом с равными осями.

Мера считается по **уплощённому контуру**, а не по узлам: узлы стоят где попало,
а форма — это кривая.

**Допуск соразмерен самому контуру, а не кропу.** Доля от его размера, а не
пиксели: у рамки в пятьсот пикселей и у кружка в полсотни «похоже» означает
разную абсолютную точность. С абсолютным допуском рамка иконки «play»
отклонялась на 13 px при размере 560 — это 2.4%, и она не признавалась
скруглённым прямоугольником, хотя им является.

**Правильность многоугольника проверяется, а не подразумевается.** Первая
версия вписывала n-угольник по крайним точкам и называла его правильным —
так любой кособокий треугольник получал звание. Теперь сверяются длины сторон
и углы, и имя честное: «правильный треугольник» или просто «пятиугольник».

**Программа предлагает, а не применяет.** У похожего контура в редакторе
появляется строка с именем и отклонением, рядом кнопка; до нажатия не меняется
ничего. Иногда картошка и задумана картошкой. Применение — обычная операция
редактора: отменяемая и отчуждающая контур.

Известное упущение: кольцо даёт два контура, и они приводятся поодиночке.
Центры при этом сходятся сами (у иконки «play» рамка дала 13.40 и 13.86 px),
но общий центр не навязывается — при сильном перекосе штрих может поплыть
по толщине.

## 5. Воркер

Весь путь «параметры → Shape» уезжает в один воркер `js/worker/pipeline.js`.
Воркер докладывает о готовности сообщением `ready` и о любом сбое — сообщением
`error`: молчащий воркер снаружи неотличим от пустой панели.

```
main → worker  { type:'crop',   gen, imageData }   // один раз, transferable
main → worker  { type:'params', gen, params }      // на каждое движение ползунка
worker → main  { type:'preview', gen, mask }       // маска для показа
worker → main  { type:'shape',   gen, shape }
```

Кроп уезжает один раз и остаётся в воркере — на каждое движение ползунка
летят только параметры. Устаревшие ответы отбрасываются по счётчику `gen`:
главный поток увеличивает его на каждое изменение, воркер штампует им ответы,
приход с меньшим `gen` игнорируется. Воркер дополнительно проверяет флаг
«пришли новые параметры» перед дорогим шагом трассировки и бросает работу.

Дребезг ползунков — 100 мс. Обоих механизмов мало по отдельности: маска
иконки 22×19 после апскейла ×8 — это 176×152, трассируется мгновенно, а маска
строки текста после ×4 — 6000×800, и там счётчик поколений спасает от очереди
из десяти устаревших трассировок.

## 6. Маршрут шрифта

```
маска строки
   │
   ├─ segment ──→ Component[]        связные компоненты (8-связность) по бинарной
   │                                 маске; в компонент кладётся МЯГКАЯ маска,
   │                                 обрезанная по метке
   ├─ merge ────→ Group[]            склейка Ё Й i j ! ? : ; по перекрытию
   │                                 + ручные «объединить» / «разделить»
   ├─ trace × N ─→ Shape[]           каждая группа трассируется отдельно
   │
   ├─ assign ───→ codepoint          ← текст, введённый человеком
   │
   ├─ metrics ──→ Glyph[]            ← направляющие, протянутые человеком
   │
   └─ export/font ─→ .otf .woff2
```

**Единица формы в шрифтовом маршруте — буква, а не кроп.** Лист со ста знаками
огромен, но каждая буква на нём невелика, поэтому допуски соразмеряются с её
габаритом, внутри `traceGroup`. Отсев мусора при сегментации тоже относительный:
доля от размера обычной буквы, иначе точка над «ё» отсеивается вместе с шумом.

Отсюда неочевидное следствие: допуски надо пересчитывать **при смене маршрута**,
а не только при новом кропе. Кроп обычно делают ещё в иконочном режиме, и без
пересчёта на лист уходил порог, рассчитанный на всю картинку, — все буквы
пропадали разом, а панель показывала бодрые «68 глифов» с пустыми очертаниями.

**Ключевое решение: разветвление происходит до трассировки, а не после.**
Сегментируем растр, потом трассируем каждый глиф отдельно. Причины:

- каждый глиф получает свой бюджет апскейла — буква высотой 14 px и буква
  высотой 22 px требуют разного `k`;
- перетрассировка одной буквы не трогает остальные;
- дырки в «О» и «Ф» выходят сами собой из трассировки подкартинки — не нужно
  потом группировать контуры по вложенности и гадать, чья дырка чья.

Альтернатива «трассировать весь кроп, потом разложить контуры по буквам»
требует анализа вложенности и разбора направления обхода на чужих данных.
Отвергнута.

Тонкость, которую легко потерять: компоненты ищутся по **бинарной** маске
(связность определена только для битов), а на трассировку уходит **мягкая**
маска, обрезанная по найденной метке. Иначе весь выигрыш от антиалиасинга,
ради которого затевался пункт 0, теряется на маршруте шрифта.

Склеек три, и каждая знает то, чего не знают другие.

**Первая — по перекрытию.** Два компонента объединяются, если их диапазоны
по X пересекаются больше чем на половину узкого, а вертикальный зазор меньше
0.4 высоты высокого. Покрывает Ё, Й, i, j, точку в ё, двоеточие, кавычки —
всё, где часть стоит НАД частью.

**Вторая — по тесноте.** «Ы» это «Ь» и «І» бок о бок, перекрытием их не
собрать. Зато выдаёт зазор: в строке «ХЦЧШЩЪЫЬЭЮЯ» промежутки между буквами
31–56 пикселей, а внутри «Ы» — семь. Мера берётся из самой строки: всё, что
заметно теснее её медианы, — одна буква. Ширина сдерживает, чтобы при плотной
посадке не слиплись два настоящих знака.

**Третья — по известному числу знаков.** У шрифтового листа есть то, чего нет
у случайной картинки: человек уже сказал, что написано. Значит известно,
сколько знаков в строке, и гадать незачем — лишние группы склеиваются по самым
тесным зазорам, пока их не станет ровно столько. Многоточие из трёх точек,
процент из трёх частей, «™» сводятся сами.

Обратное неверно: если групп МЕНЬШЕ ожидаемого, два знака слиплись, и разнять
их автоматика не берётся — об этом говорится вслух, с номерами строк.

На тринадцати листах из `glyph-sheets/` (шесть начертаний, кириллица и латиница
со знаками) три склейки вместе дают ноль промахов: 66 знаков кириллицы,
104 латиницы со знаками.

**Единица формы в шрифтовом маршруте — буква, а не кроп.** Лист со ста знаками
огромен, но каждая буква на нём невелика, поэтому допуски соразмеряются с её
габаритом, внутри `traceGroup`. Отсев мусора при сегментации тоже относительный:
доля от размера обычной буквы, иначе точка над «ё» отсеивается вместе с шумом.

Отсюда неочевидное следствие: допуски пересчитываются **при смене маршрута**,
а не только при новом кропе. Кроп обычно делают ещё в иконочном режиме, и без
пересчёта на лист уходил порог, рассчитанный на всю картинку: все буквы
пропадали разом, а панель бодро показывала «68 глифов» с пустыми очертаниями.

Порядок для `assign`: строки сверху вниз (кластеризация по перекрытию bbox
по Y), внутри строки слева направо. Пробел в тексте не потребляет группу,
но считается и запоминается — на этапе метрик по нему берётся ширина пробела.

**Расхождения не выравниваются хитростью.** Соблазн был: подобрать наилучшее
соответствие между строкой текста и рядом глифов, раз уж одна буква могла
распасться надвое. Но всякий такой подбор — догадка, а догадка тут молча
испортит весь ряд после места ошибки. Поэтому привязка простая, один к одному,
а расхождения возвращаются числами: строк текста столько, рядов букв столько,
эти символы остались без глифа, эти глифы без символа. Правит человек — либо
склейкой на предыдущем этапе, либо полем «символ» поштучно.

Ручные правки привязки не переживают перегруппировку: после новой сегментации
индексы глифов другие, и делать вид, что привязка их пережила, было бы враньём.
Текст при этом остаётся, так что перепривязка стоит одного нажатия.

**Покрытие алфавита** — ради него всё и затевалось. Если кроп содержит лишь
часть символов, человек должен увидеть, каких именно не хватает, и пойти
сгенерировать картинку с ними, а не гадать. `coverage()` сверяет набор
с одним из готовых алфавитов и показывает недостачу списком.

## 7. Редактор

Операции — **чистые функции над `Shape`**, ни строчки DOM:

```js
insertNode(shape, {ci, ni, t}) -> Shape     // t — параметр на кривой, де Кастельжо
removeNode(shape, {ci, ni})    -> Shape
moveNodes(shape, selection, delta) -> Shape
moveHandle(shape, {ci, ni, which}, pt, {mirror}) -> Shape
setNodeType(shape, {ci, ni}, type) -> Shape
```

Из чистоты бесплатно следует и отмена (снимки, а не обратные операции —
`Shape` маленький, сотни узлов), и тестируемость.

`history.begin()` / `history.end()` оборачивают перетаскивание, чтобы drag
мышью стал одним шагом отмены, а не сорока.

**Рендер — гибрид.** Растровая подложка (исходник и маска) — в `<canvas>`;
вектор, узлы и рычаги — в `<svg>` поверх. SVG даёт попадание курсором даром
через `pointer-events`, а с ним фокус с клавиатуры и доступность. Рисовать
узлы на канве — значит писать собственный hit-testing, которого можно не
писать.

## 8. Метрики: математика

```
k  = capUnits / (baseline − capHeight)          // по умолчанию capUnits = 700, upm = 1000
x' = (x − bboxLeft) · k + lsb
y' = (baseline − y) · k                         // единственный переворот Y во всей системе

advance   = lsb + width · k + rsb
ascender  =  k · (baseline − capHeight) · 1.05
descender = −k · (descender − baseline)
```

Боковые отступы по умолчанию не берутся с потолка: между соседними
компонентами в картинке измеряются зазоры, берётся медиана, делится пополам.
Рисовавший иконку уже выбрал расстояние между буквами — надо его прочитать,
а не придумывать. Ползунок остаётся, но начальное значение осмысленное.

Ширина пробела измеряется там же: зазоры вдвое с лишним шире медианного —
это словоразделы, их медиана и есть пробел. Если таких нет, берётся 250 units.

**У каждой строки своя базовая линия, а высоты — общие смещения от неё.**
Иначе на шрифтовом листе из шести рядов медиана низов ложится между рядами,
и «глубина выносных» оказывается расстоянием до нижнего ряда: выходило −4023
единицы вместо полутора сотен. Четыре направляющие, которые тянет человек,
описывают одну строку — самую населённую, у неё статистика надёжнее; остальные
следуют за своими базовыми линиями сами.

**Догадка о направляющих.** Базовая линия — медиана низов, а не самый нижний
низ: выносные элементы («р», «у», ножки «Д») её тогда не утаскивают, пока их
меньше половины. Глубина выносных — как раз самый нижний низ. Верхи разбиваются
надвое по наибольшему разрыву в ряду: если разрыв заметен, в кропе есть и
прописные, и строчные; если нет, все буквы одного роста, и строчная ставится
по обычному соотношению 0.72 — иначе направляющая легла бы на базовую линию
и тянуть её было бы не за что.

**Переворот Y сам чинит обход.** В crop-пространстве внешний контур идёт по
часовой, а CFF ждёт против. Отражение оси меняет знак площади, то есть после
`toGlyphSpace` обход уже такой, какой нужен, и вызывать `orient` ещё раз не
надо — это была бы двойная работа с обратным результатом.

Пробел: группы нет, `advance` задаётся отдельно.

## 9. Состояние и хранение

Маленький наблюдаемый store, без фреймворка, порядка восьмидесяти строк:

```js
subscribe(topic, fn)      // topics: source params shape glyphs metrics selection ui
set(topic, patch)
```

Панели интерфейса подписываются на темы и остаются глупыми. Логика в store не
живёт — только состояние и оповещение.

IndexedDB: одна запись на проект, запись с дребезгом 500 мс по темам
`shape` / `glyphs` / `metrics`. Исходная картинка хранится Blob'ом (PNG),
а не сырой `ImageData` — разница на порядок.

## 4г. Метрика расхождения и авто-подбор

Качество обводки — число, а не впечатление: контур рендерится обратно в растр
(`trace/rasterize.js`, свой сканлайн с ненулевым правилом, без DOM) и
сверяется с бинарной маской, по которой обводили. Мера — СРЕДНИЙ УВОД КРАЯ:
площадь симметрической разности, делённая на длину края, в пикселях маски.
Доля от площади не годится: у тонкоштриховой иконки площадь мала, а периметр
велик, и честные полпикселя гуляния края выглядели бы страшными пятнадцатью
процентами, а у жирной буквы — невинным одним. Отдельно — разница числа
компонент (крапины мельче «Мусора» не в счёт): потерянная точка над «ё» не
должна тонуть в среднем. «Расхождение» всегда стоит в сводке.

Авто-подбор (`tune/tune.js` — чистый спуск, тестируется на подделке мира;
воркер даёт ему evaluate из тех же iconJob/fontJob, что гоняет обычный цикл).
Цель — баланс, а не минимум узлов под потолком: правило владельца «семь
узлов при сходстве 96 % хуже восьми при 99 %». Узел стоит фиксированную
долю увода (`NODE_COST` = 0.02 px на узел на букву), минимизируется
`увод + NODE_COST·узлов/букв`; потолок — предохранитель (полуторный
исходный увод, не строже) и ни одного потерянного куска. Прежний
лексикографический минимум на настоящем Lato сбрасывал четверть узлов,
утраивая увод от истинных контуров (0.16 → 0.54 px); балансный на тех же
узлах увод уменьшает (0.155 → 0.142).
Подбор уступчив: перед каждым прогоном отдаёт очередь сообщений, и любое
движение ползунка его обрывает. Найденные значения открыто встают в те же
ползунки, что крутит человек, — никакого скрытого состояния. Узлы подбор
не двигает: это оптимизация формы, а не параметров, — граница из замысла.

## 4д. Сверка с настоящими шрифтами: что показали Lato и FreeSerif

В `font_ref/` лежат два листа, у которых есть ИСТИНА: текст, переведённый
Inkscape в контуры (`.svg`) и им же отрендеренный (`.png`, 100 dpi, кегль
с прописными около 32 px). Пиксель PNG и миллиметр SVG связаны точно
(`(x − translate)·100/25.4`, плюс замеренная поправка экспорта — Inkscape
округляет холст до целых пикселей), так что каждую обведённую букву можно
сверить не с маской, а с контуром, который её породил. Отсюда три меры:
увод от истины (px), число узлов против «канона» истины (её же контуры,
пропущенные через наш regularizeShape с тем же допуском) и структура —
сколько углов истины найдено, найдено гладкими, пропущено.

Что нашлось (Lato, 122 буквы; было → стало):

- **Контур лежал выше-левее истины на 0.5/scale.** Изолиния считается между
  ОТСЧЁТАМИ (x, y), а пиксель x покрывает [x, x+1): отсчёт — центр пикселя.
  `traceMask` и осевая теперь отдают `(p + 0.5)/scale`; ось свёртки — так же.
  Так же видит пиксель рендер расхождения и SVG поверх картинки.
- **Порог стоял ДО изолинии.** Увеличенная маска бинаризовалась, и изолиния
  шла по лесенке: край квантовался к сетке увеличения — четверть пикселя
  исходника при ×4. Это ставило лишние узлы на прямых кромках и сбивало
  вершины углов. Теперь морфология и изолиния идут по серому полю на уровне
  «Порога»; бинарная маска — только для показа, сегментации и метрики.
  Сырая обводка: 7108 → 2120 узлов при уводе 0.13 → 0.11 px.
- **Покрытие → поле** (`coverageToField`): пиксель с покрытием c между
  полным и пустым имеет край в c от своего левого края, а линейная
  интерполяция между центрами ставит его в 0.5/(1−c) — промах до 0.08 px.
  Монотонная кривая g(v) = 2v/(1+2v) | 0.5/(1.5−v) снимает промах, 0.5
  остаётся на месте — порог показа не меняется.
- **Углы мерились хордами от самой вершины.** Антиалиасинг скругляет угол на
  0.5–1 px исходника, хорда ныряет в скругление, и прямой угол буквы в
  тридцать пикселей мерился в 50° — пропадал. Теперь меряются ПЛЕЧИ: от
  отступа 0.4·окна до окна; окно не мельче двух пикселей исходника (буква
  мелкая, а скругление — нет). Плечо вершины при заострении — от пикселя до
  двух от неё, по точкам ВДОЛЬ рёбер многоугольника (упрощение выкидывает
  вершины прямой, и внутри плеча не оказывалось ни одной). Гашение точек у
  вершины — не меньше пикселя исходника. Углов истины найдено 314 → 717
  из 819, пропущено 378 → 66.
- **Примитив принимался по доле габарита.** 2.5 % от «О» в сорок пикселей —
  целый пиксель; «О» Lato эллипсом не рисовалось и уводилось на 0.33 px.
  Допуск примитива — тот же, что у всего канона (`primTol`).
- **Выравнивание толщин двигало грань до 0.8 px.** На настоящем шрифте
  стойки прописных, строчных и знаков разной толщины ПО ЗАМЫСЛУ: «I» и «T»
  уводились на 0.4 px — вчетверо хуже сырой обводки. Потолок сдвига — допуск
  обводки, группа — две толщины допуска.
- **Осевые узлы после зеркальной пересборки** оставались на прямых кромках
  («I» — 8 узлов вместо 4); снимаются `dropCollinear` — узел на оси, симметрию
  не трогает.

Итог: Lato 2172 → 1599 узлов (канон истины 1542, 1.04×), увод от истины
0.245 → 0.155 px; FreeSerif 3456 → 2783 (канон 2878), 0.225 → 0.158 px.
Разбор листа — 1.3 с вместо 3.7.

Как устроены буквы — из тех же контуров, теперь в `glyphs/priors.js`
(таблица «знак → узлов у сансерифа, у антиквы, контуров, углов»; подпись
плитки и сводка привязки говорят «узлов 14, обычно 12–28»):

1. Прямые буквы — одни углы: Н 12, П 8, Т 8, Ш 12, Г 6; ни одного гладкого.
2. Дуги — узлы на экстремумах с осевыми рычагами, кусок не длиннее
   четверти; у надутых колец Lato ещё узел между экстремумами.
3. Стык прямой и дуги — один гладкий узел на касательной.
4. Число углов — самое устойчивое; засечки добавляют по четыре на каждую:
   антиква в среднем в 1.6 раза тяжелее сансерифа (20 против 12.5 на знак).
5. TrueType-контуры вдвое-втрое гуще кубических (Lato 3442 узла против
   1596 в кубиках): ожидание считать после перевода в кубики.

Не взялось: «ы» и «№» Lato режутся на части — зазор внутри буквы не теснее
медианного в плотно набранной строке; собирает их подгонка под введённый
текст, как и в приложении. У антиквы пропущено 400 углов из 1658 — бракеты
засечек радиусом в пиксель-два на этом кегле неотличимы от скругления
антиалиасинга; на листах крупнее это уходит само.

## 4е. Сборка из примитивов

Третье представление рядом с заливкой и осевой (`assemble/`): не узлы с
рычагами, а список примитивов с параметрами — круг, прямоугольник и
скруглённый прямоугольник (с поворотом), капсула, отрезок, ломаная,
многоугольник, скруглённый многоугольник (радиус у каждой вершины свой,
острые допускаются), путь из отрезков и дуг, залитое пятно. SVG из неё —
настоящие `<rect rx>`, `<circle>`, `<line>`, `<polyline>`, `<path>` с L и A,
одна толщина штриха на иконку; наружу в холст она отдаётся обычной фигурой
(`assemblyToShape`: дуги — кубиками по касательным), так что показ и правка
те же. Замысел владельца: монолайн-иконки рисуются циркулем и линейкой,
и описывать их надо тем же языком.

Путь:

1. **Пятна отдельно.** Компонента, у которой толщина (по преобразованию
   расстояний) не меньше 0.7 габарита, — точка «i», кружок тумблера —
   идёт заливкой: скелет пятна отсеивается как отросток, и точка пропадала.
2. **Осевая → сквозные цепочки.** `centerline` рвёт линии в развилках.
   `stitchThrough` в каждой развилке сшивает пару концов, продолжающих друг
   друга (встречные направления): стойка «Т» не рвёт перекладину, уши робота
   не рвут голову, ножка антенны не рвёт кольцо — оно замыкается. Точки в
   0.8 толщины от развилки гасятся: скелет там ныряет к ветви.
3. **Куски.** `pieces.segmentChain` — разбор цепочки на отрезки и дуги
   наименьшим числом кусков (динамическое программирование по вершинам
   упрощённой ломаной, проверка каждого куска по ПЛОТНЫМ точкам). Жадный
   разбор промахивался: отрезок, дотянувшийся в допуске до начала скругления,
   съедал его начало, и на остаток ложилась дуга не того радиуса. Дуга чуть
   дороже отрезка (0.5 куска): на прямой с шумом окружность огромного радиуса
   «ляжет» всегда. Кольцо режется в произвольной точке — шов сшивается.
4. **Узнавание по составу кусков** (`recognizeClosed`): круг — все точки на
   одной окружности (усечённая проверка: у развилок пара процентов точек
   законно выбивается); стороны — ДЛИННЫЕ отрезки (не короче 1.2 толщины),
   между ними соединители углов — дуги или короткие срезы (скелет мелкой
   маски режет скругление наискось; радиус из длины среза: хорда четверти —
   r·√2). Размеры прямоугольника — по опорным прямым сторон, не по длинам
   отрезков: дуги съедают у сторон разное. Пологая дуга большого радиуса —
   не угол, а выгнутая сторона (картинка не идеальна). Эвристики нарочно
   мягкие, потому что
5. **догадку проверяет геометрия** (`fitsChain`): примитив принимается, если
   его ломаная лежит на точках осевой в пределах 2 допусков (или 0.35
   толщины); иначе остаётся путь из кусков — тоже точный, только без имени.
6. **Растр против маски.** Каждый кусок — капсула с круглыми концами (концы
   через продолжение оси: иначе полукруг уходил внутрь полосы и капсула
   становилась бантом), пятна — как есть; всё с положительным обходом —
   ненулевое правило даёт объединение. `mismatch` — тот же увод края.

Развилки. Ветвь заканчивается не в точке развилки скелета, а там, где её
ПРОДОЛЖЕНИЕ встречает соседей (`extendToJunctions`): у острия стрелки
развилка стоит на полтолщины раньше острия, и ножки не сходились. Точки в
0.8 толщины от развилки гасятся, короткий концевой кусок (остаток нырка
скелета к ветви) снимается, а концевая дуга продолжается касательной, не
разворотом. Направление конца цепочки для сшивки меряется в глубине, от
двух толщин до одной: по самому концу ножки стрелки выглядели встречными
(cos −0.83) и сшивались сквозь острие. Радиус скруглённого прямоугольника —
подгонкой по точкам осевой, а не по дугам кусков (`refineRadius`).

**Урок про утоньшение** (поймано на «×»): Чжан — Сунь снимает пиксели
с двумя-шестью соседями, а у концевой пары двухпиксельной диагональной
лесенки соседей ровно два — пара снималась целиком за проход, и полоса
съедалась с конца до развилки: луч в 300 px исчезал без следа, три других
луча (другого наклона) уцелели случайно. Нижняя граница поднята до трёх:
два соседа — уже линия, её не трогаем (`trace/centerline.js`, `thin`).

Замер на полном монолайн-наборе — 96 иконок 1254 px (`monoline/big`,
`node monoline/assemble.mjs`, 2.5 минуты): средний увод от маски 1.36 px
(0.1 % размера), хуже 2.5 px — шесть иконок (часы, месяц, щит, секундомер,
скобки, папка), потерянных кусков нет. Примитивов: 30 кругов, 11 скруглённых
прямоугольников (в том числе тумблер-капсула и «стоп»), 4 скруглённых
многоугольника, 129 отрезков, 31 ломаная, 28 пятен; 162 пути из отрезков и
дуг — молния, гем, искра, дискета, шестерёнка, ключ: точные, честно
безымянные. Робот — 8 примитивов при уводе 0.8 px. Стрелки сходятся в
остриях, «×» — два отрезка через центр.

Не сделано: правка ПАРАМЕТРОВ примитива в редакторе (сейчас правятся узлы
фигуры, и сборка при этом отчуждается как любая правка); несколько слоёв
сборкой в одном SVG (уходит кривыми, о чём говорится); декомпозиция
залитых силуэтов на объединение примитивов.

## 5а. Воркер: хвост цикла — в finally

Урок стоимостью в «приложение выглядит живым, но мертво». Цикл воркера держит
флаг занятости; шрифтовая ветка выходила через return до его сброса, и после
первого же шрифтового прогона все следующие запросы ложились в pending,
который никто не забирал. Ни ошибки, ни зависания — просто тишина: ползунки
перестают действовать. Сброс флага и перезапуск очереди живут в finally —
из-под него не выйти ни ранним return, ни исключением.

Признак этой болезни снаружи — «то работает, то нет»: до первого шрифтового
прогона всё пересчитывается, после — ничего.

## 9а. Шаги интерфейса

Конвейер виден снаружи: интерфейс разложен по шагам, и шаг — единственная
переменная, решающая, что показывает рабочая область и какая панель раскрыта.

```js
STEPS.icon = ['image', 'mask', 'contour', 'export']
STEPS.font = ['image', 'mask', 'glyphs', 'metrics', 'font']
VIEW       = { image|mask|contour|metrics|export → 'stage',
               glyphs → 'grid', font → 'font' }
```

Рабочая область `#work` держит три вида друг на друге: стол `#stage`, сетку
букв `#grid-view`, пробу пера `#font-view`. Показан ровно один, и решает это
ЕДИНСТВЕННАЯ функция `syncView()` — производное от (шаг, правка буквы), а не
хранимое состояние. Пока видимость щёлкали три места независимо, рассинхрон
давал то пустую сетку, то зум без стола. Панель —
набор секций `.step-panel[data-step]`, раскрыта тоже ровно одна. Отсюда
правило, ради которого всё затевалось: **настройка стоит рядом с тем, на что
влияет**. Ползунки кривых живут не в одном месте, а там, где смотрят их
результат: на «Контуре» в иконочном маршруте, на «Буквах» в шрифтовом, —
`buildControls()` раскладывает группы по контейнерам шага.

Три частности, которые стоили отладки и потому записаны:

- Виды прячутся атрибутом `hidden`, но `.font-view` задаёт свой `display`, и
  без `[hidden] { display: none !important }` спрятанная проба продолжала
  рисоваться поверх сетки.
- Маска живёт в увеличенном разрешении, а стол размечен в пикселях кропа:
  на стол она кладётся с явным размером кропа, иначе уезжает за поле.
- Подложка (маска · растр · вместе) — свойство стола, а не шага, и
  переключатель висит на самом столе. Иначе на «Контуре» растр видно, а
  убрать его нечем — ровно та жалоба, с которой началась разбивка на шаги.
- Указатель на столе приходит в координатах ТОГО, что на столе лежит: на
  «Картинке» — исходника, дальше — кропа. Пипетка обязана читать пиксели из
  того же массива. Пока она читала исходник координатами кропа, щелчок по
  штриху давал цвет из другого места картинки; чаще всего фоновый — и он
  уходил в «Штрих», отчего маска выворачивалась, а экспорт выдавал негатив.
  Одна ошибка в пространстве координат — три разные жалобы (инвариант 4).

## 9б. Слои: несколько чернил на кропе

```js
Layer   = { id, name, fg:[r,g,b], tolerance, shape, visible }
```

Фон общий: он у кропа один, разные только чернила. Параметры маски
(увеличение, порог, морфология) и кривых тоже общие — они про растр, а не про
цвет. У слоя своё только два: цвет штриха и допуск. Это держит панель в
разумных размерах: один набор ползунков плюс список слоёв.

Конвейер для каждого слоя тот же: `colorDistance` со своим цветом →
увеличение → порог → морфология → обводка. Три места, где порядок важен:

- **Спор за пиксель решается до увеличения.** Спад яркости между двумя
  цветами принадлежит обоим сразу; «победитель забирает всё» отдаёт пиксель
  слою с наибольшим мягким значением. Разбирать надо на исходном растре, где
  спор и возник, а не на домысленных лишних пикселях.
- **Ось симметрии ищется один раз по общей маске** и навязывается каждому
  слою (`symmetrize({ atX, atY })`). Иначе каждый слой найдёт ось по своим
  чернилам, оси разойдутся, и слои разъедутся на пиксель-другой.
- **Граница владения общая, а не послойная.** Параметры маски и кривых общие,
  и замораживать их для одного слоя, оставив живыми для другого, было бы
  враньём. Первая правка любого слоя отчуждает всю работу.

Шрифтовой маршрут одноцветен по своей природе — строка текста набрана одними
чернилами — и слои в него не протаскиваются: воркер берёт первый.

Догадка о чернилах (`guessInks`) — k-средних по пикселям, далёким от фона.
Начальные центры берутся жадно, без случайного старта: одна и та же картинка
обязана давать один и тот же ответ, иначе ползунок не подкрутить.

## 9в. Осевая линия

`traceStroke` отвечает на другой вопрос, чем `traceMask`: не «где граница
фигуры», а «по какой линии она начерчена и какой толщины». Выход тот же Shape
в crop-пространстве, но контуры РАЗОМКНУТЫ и у каждого есть `width`.

Порядок: точное преобразование расстояний (Фельценсвальб) → утоньшение
Чжана — Суня → снятие лесенки по Холту → разбор скелета на цепочки → сварка →
отсев отростков → упрощение и подгонка тем же аппроксиматором.

Четыре места, где наивная реализация врёт:

- **Лесенка.** Чжан и Сунь оставляют на пологих диагоналях линию в два
  пикселя, и каждый второй пиксель в ней — развилка: у кольца в 1254 px
  выходило 884 развилки и 1456 обрывков. Числом пересечений это не лечится
  (соседи связаны в обход), лечится проходом Холта.
- **Отсев меряется толщиной, а не пикселями.** Каждая ступенька на границе
  отращивает от оси ребро примерно в половину толщины: на иконке в 48 px это
  три пикселя, на мастере в 1254 — тридцать. Порог в пикселях годится только
  для мелких. Толщина берётся с самого скелета, медианой.
- **У допусков есть пол.** Осевая идёт по пиксельной сетке и ступенчата сама
  по себе, шум около полупикселя. Допуск мельче не уточняет фигуру, а
  протоколирует ступеньки: у кольца выходило 1134 узла вместо сотни.
- **Порядок: отсев → сварка → отсев.** Пока ус на месте, вершина с усом
  выглядит развилкой, сшивать в ней нельзя, и кольцо остаётся десятком дуг.

Признанная неточность: на ЧЁТНОЙ толщине ответ занижен на полпикселя. Ось
такой полосы проходит между пикселями, а скелет шириной в пиксель туда не
встанет и ложится на одну из сторон. Округлять вверх хуже — тогда занижение
сменится завышением, а на нечётной толщине пропадёт точность.

## 10. Что тестируем

Автотестами — то, где есть чистая функция и проверяемый ответ:
`core/*`, `prep/mask` на фикстурах, `glyphs/segment`, `glyphs/merge`,
`glyphs/assign`, `glyphs/metrics`, `export/svg`, `editor/ops`.

Не тестируем: обвязку воркера, `trace/*` (чужой WASM), интерфейс.

Браузерное живёт в `tests/browser.html` и требует сервера: канва, кроп и
антиалиасинг настоящего браузерного рендера. Внешних картинок оно не требует:
тонкоштриховую фигуру с мягкими краями страница рисует сама. Смотровые стенды
(`*-visual.html`) показывают наборы картинок, когда те лежат рядом, — в
репозиторий картинки не входят.

## 12. Отвергнутое

Чтобы не пересматривать по кругу.

| Что | Почему нет |
|---|---|
| Порог до апскейла | Выбрасывает 81% информации о крае (см. п. 0). |
| Битовая маска как основной тип | То же самое, только раньше и незаметнее. |
| Перенос правок на новую трассировку | Идентичность узла не переживает смену параметров; выйдет эвристика, которая молча портит работу. |
| Трассировать весь кроп, потом делить на буквы | Требует разбора вложенности контуров и направления обхода. Сегментация по растру проще и точнее. |
| VTracer (готовый трассировщик) | Обводит границы пикселей, то есть выбрасывает субпиксельный край — ровно то, ради чего перевёрнут конвейер. И отдаёт строку пути: где стык гладкий, а где угловой, пришлось бы угадывать, а редактору нужен точный тип узла. Свой трассировщик знает это по построению. |
| Допуски в пикселях увеличенной маски | Ползунок увеличения молча менял бы плотность узлов. Наружу всё выражено в пикселях исходника. |
| Поиск угла по соседним вершинам | Фаска маршевых квадратов превращает прямой угол в два по 45°; распознавание начинает зависеть от настройки упрощения. |
| OCR для привязки символов | На декоративном шрифте врёт увереннее, чем помогает. Текст вводит человек. |
| TTF вместо OTF | Квадратичные кривые в `glyf` — лишняя конверсия на каждом узле. CFF принимает кубические как есть. |
| Отмена через обратные операции | `Shape` маленький, снимки проще и надёжнее. |
| Узлы и рычаги на канве | Пришлось бы писать собственное попадание курсором и доступность. |
| Фреймворк | Ваниль, как в Charsets и MDEditor. Store на восемьдесят строк закрывает нужду. |
