# Пантограф

Снять контур с растровой картинки: иконку — в SVG, набор букв — в шрифт.
Полностью в браузере, без сервера.

Этот документ — что делаем и в каком порядке. Как оно связано внутри —
в [ARCHITECTURE.md](ARCHITECTURE.md); отложенное — в [BACKLOG.md](BACKLOG.md).

## 1. Название

**Пантограф** — чертёжный прибор, который копирует рисунок, меняя масштаб.
В шрифтовом деле это не метафора: пантограф Бентона в конце XIX века переносил
нарисованную букву на пуансон и стал станком, на котором держалась вся
индустрия наборного шрифта. Инструмент делает ровно это же.

| Имя | | Почему |
|---|---|---|
| **Пантограф** | рекомендую | Точное имя, а не описание. Покрывает обе половины проекта — и иконки, и шрифт, — потому что говорит о копировании контура вообще. Хорошо звучит по-русски и латиницей. |
| Tracery | запасной | Готическое каменное кружево и одновременно «обводка». Минус: так называется известная библиотека генеративных грамматик Кейт Комптон. |
| Punchcut | если про шрифт | Пуансонист — тот, кто вырезал буквы в металле. Сильное имя, но иконочная половина остаётся за бортом. |
| Vectorium | родня Idyllium | Рифмуется с соседним проектом, но описывает механику, а не смысл: так можно назвать любой векторный редактор. |

## 2. Что делает инструмент

Два маршрута с общим низом.

- **Иконка**: кроп → препроцесс → трассировка → упрощение → правка узлов → SVG.
- **Шрифт**: то же, но между трассировкой и правкой вклиниваются сегментация на
  глифы, привязка к символам и разметка метрик; на выходе `.otf` и `.woff2`.

Инструмент выдаёт **черновик контура, а не готовую иконку**. Это позиция, которую
интерфейс занимает открыто: редактор стоит в центре конвейера, а не прячется
опцией под кнопкой «дополнительно».

## 3. Ядро: единый формат контура

Главное архитектурное решение, принимается до первой строчки кода. Все модули
говорят на одном внутреннем представлении; SVG появляется только на границе
экспорта. Гонять SVG-строки между стадиями — верный способ к четвёртому этапу
получить парсер путей в каждом файле.

```js
// на этом говорят трассировщик, упрощатель, редактор и сборщик шрифта
Node    = { p:{x,y}, in:{x,y}|null, out:{x,y}|null, type:'smooth'|'corner' }
Contour = { closed: true, nodes: Node[] }
Shape   = { contours: Contour[], fillRule: 'nonzero' }

Glyph   = { codepoint, shape: Shape, bbox, advance,
            source: { cropId, componentIds:[] } }

Metrics = { upm: 1000, baseline, xHeight, capHeight, descender }

Project = { image, crops:[], shapes:[], glyphs:[], metrics, settings }
```

Кривые держим кубическими: такими их строит трассировщик, такими их принимает
SVG, такими их принимает таблица CFF в `.otf`. Ни одного преобразования между форматами кривых
на всём пути — ради этого свойства выбран OTF, а не TTF.

## 4. Карта модулей

| Модуль | Что делает |
|---|---|
| `core/path` | Узлы, контуры, фигуры. Геометрия, bbox, обход, направление. Ни на что не ссылается. |
| `core/simplify` | Рамер — Дуглас — Пекер для разомкнутой и замкнутой полилинии. |
| `prep/crop` | Загрузка, зум и панорама, прямоугольное выделение. На выходе ImageData. |
| `prep/mask` | Мягкая маска 0..1 по цветовому расстоянию, апскейл Lanczos ×4–×8, **порог после апскейла**, морфология. Единый тип `Mask` на всех шагах. |
| `trace/trace` | Изолиния маршевыми квадратами, поиск углов, сборка узлов. Отдаёт Shape. |
| `core/bezier` | Подгонка кубических кривых по Шнайдеру. |
| `glyphs/segment` | Связные компоненты плюс проекционные профили по строкам и колонкам. |
| `glyphs/merge` | Склейка составных букв по перекрытию bbox. Эвристика — значит, с ручной правкой. |
| `glyphs/assign` | Сопоставление компонент с текстом, который ввёл пользователь. |
| `glyphs/metrics` | Направляющие, нормализация в upm, ширины и боковые отступы. |
| `editor/nodes` | Выбор, тяга, рычаги, вставка и удаление узла, смена типа, привязка к сетке. |
| `editor/history` | Отмена и повтор поверх снимков Shape. Отдельно, чтобы редактор не знал про историю. |
| `export/svg` | Shape → строка пути. Единственное место, где рождается SVG. |
| `export/font` | opentype.js: глифы, метрики, имена, `.otf` и `.woff2`. |
| `project` | Что считается работой: снимок, восстановление, перенос одним файлом. |
| `idb` | Проект в IndexedDB. Как в MDEditor: пишем по факту правки, а не по кнопке. |
| `export/zip` | Запись и разбор zip своими силами, на `CompressionStream`. |

## 5. Порядок сборки

Порядок выбран по риску, а не по удобству: этап 1 отвечает на вопрос «получается
ли вообще приличный контур с картинки такого разрешения» до того, как в редактор
узлов вложены две тысячи строк.

### Этап 0 — Скелет и кроп ✔
Страница, загрузка перетаскиванием, холст с зумом и панорамой, прямоугольное
выделение с ручками. Никакой обработки.
**Готово, когда:** фрагмент отдаётся дальше как ImageData и виден превьюшкой
с указанием размера в пикселях.

### Этап 1 — Препроцесс и первая трассировка ✔
Пипетка по цвету, мягкая маска 0..1 по цветовому расстоянию, апскейл Lanczos,
порог **на высоком разрешении**, морфология, трассировка. Результат рядом
с исходником, чтобы сравнивать глазами. Порядок принципиален: 81% пикселей
иконки — краевые, и жёсткий порог до апскейла рвёт штрих (см. `ARCHITECTURE.md`, п. 0).
**Готово, когда:** жёлтая иконка «Игры» с референса (в оригинале около 22 px)
даёт узнаваемый и не волнистый контур. Это проверка гипотезы всего проекта.

**Пройдено.** Узнаваемо обводятся все пять проверенных целей пробного
референса — четыре мелкие иконки и крупный логотип. Трассировщик свой —
готовый VTracer отвергнут (см. `ARCHITECTURE.md`, п. 4а и «Отвергнутое»).

### Этап 2 — Упрощение и экспорт SVG ✔
Ползунок числа узлов поверх RDP, слияние близких узлов, скачивание файла.
**Готово, когда:** иконка скачивается как `.svg`, открывается в Inkscape
и не разваливается.

> **Веха: инструмент уже полезен для иконок.**

### Этап 3 — Редактор узлов ✔
Выбор одиночный и рамкой, тяга узлов и рычагов, вставка узла на кривой,
удаление, переключение гладкий/угловой, разрыв симметрии рычагов с Alt, сетка
и привязка, отмена и повтор. Самая объёмная часть — и самая предсказуемая,
исследовательских рисков здесь нет.
**Готово, когда:** кривую иконку удаётся руками довести до симметричной,
не выходя из браузера.

**Сделано:** выделение одиночное, с <kbd>Ctrl</kbd> и рамкой; тяга узлов и
рычагов; вставка узла двойным щелчком по кривой (форма не меняется, де
Кастельжо); удаление; переключение гладкий/угловой двойным щелчком по узлу;
<kbd>Alt</kbd> разрывает симметрию рычагов; привязка ½ px и сетка по пикселям
исходника; отмена и повтор с транзакциями на перетаскивание. Механика проверена
в браузере; «довести до симметричной» — суждение руками, за владельцем.

### Этап 4 — Сегментация глифов ✔
Связные компоненты, разбиение на строки проекционным профилем, склейка
составных букв по перекрытию bbox. Сетка превью и ручные операции
«объединить» и «разделить».
**Готово, когда:** на контрольной строке референса (тринадцать букв в два
слова) находятся ровно 13 компонент и ни одна буква не распалась.

### Этап 5 — Привязка к символам ✔
Поле «что написано на картинке», перевод строки разделяет строки. Сопоставление
один к одному в порядке чтения, расхождения правятся перетаскиванием. OCR не
берём: на декоративном шрифте он врёт увереннее, чем помогает.
**Готово, когда:** каждой компоненте присвоена кодовая точка, дубликаты
и пропуски видны в списке.

**Пройдено.** Контрольная строка раскладывается по тринадцати глифам
(пробел глифа не потребляет), на плитках проступают буквы. Разбор набора:
есть 10 из 33 русских прописных, перечислены недостающие, дубликаты показаны
как А×2 Л×2 О×2. Поле «символ» правит привязку выбранной буквы и переходит
к следующей.

### Этап 6 — Метрики ✔
Четыре направляющие — базовая линия, высота строчных, высота прописных, глубина
выносных — тянутся мышью поверх кропа. Нормализация в единицы em, ширины
и боковые отступы по bbox с общим множителем.
**Готово, когда:** буквы в превью стоят на одной линии, а не пляшут по вертикали.

**Пройдено.** На контрольной строке низы двенадцати букв из тринадцати —
в пределах полпикселя кропа от базовой линии; тринадцатая — буква с нижним
выносным элементом, её низ на −142 единицы, как и положено.
Выпадает одна «Д», и она обязана: у неё ножки ниже базовой. Круглые «О»
свешиваются на десяток единиц — норма свеса округлых.

### Этап 7 — Сборка шрифта ✔
opentype.js собирает `.otf`. Живое превью произвольной строкой прямо на
странице через `FontFace`.
**Готово, когда:** скачанный `.otf` ставится в систему и набирает текст
в постороннем редакторе.

**Пройдено.** Собранный по контрольной строке шрифт: `fc-query` видит его
как семейство с кириллическим названием формата CFF, FreeType через PIL
набирает им строку, браузер принимает через `FontFace` и набирает пробу пера.
Двенадцать глифов, три повтора отброшены — в шрифт идёт один глиф на
кодовую точку.

`.woff2` **не делаем**: он требует кодировщика Brotli отдельным wasm-модулем,
а даёт только выигрыш в размере — в `@font-face` браузеры принимают и `.otf`.
Запись заведена в [BACKLOG.md](BACKLOG.md).

### Этап 8 — Проект и пакеты ✔
Хранение в IndexedDB, экспорт zip-пакетом со всеми SVG, выгрузка и загрузка
проекта одним файлом.
**Готово, когда:** закрытая вкладка не теряет работу.

**Пройдено.** Проверено двумя запусками браузера в одном профиле: в первом
кроп, разбор на буквы, текст и название шрифта; во втором адрес открыт **без**
картинки — вернулось всё: картинка, кроп 525×46, маршрут «Шрифт», текст,
привязка всех тринадцати букв, кириллическое название, метрики 700/−144
и собранный шрифт из двенадцати глифов.

Архив пишется своими силами через `CompressionStream`, без зависимости;
проверен системным `unzip -t` и питоновским `zipfile`.

## 6. Риски

**Главный.** Иконки на референсе в оригинале около 22 пикселей. Это очень мало.
Всё, что даёт проекту право на существование, решается на этапе 1 — и решается
препроцессом, а не выбором трассировщика.

| Риск | Этап | Что делаем |
|---|---|---|
| Низкое разрешение даёт волнистый контур | 1 | Мягкая маска → апскейл ×4–×8 → порог. Именно в таком порядке. Честно показывать размер кропа, предупреждать, если сторона меньше 32 px. |
| Трассировщик даёт заливку, а не штрих: линейная иконка станет двухконтурной «трубой» | 1 | Принимаем как есть. Восстановление осевой линии — отдельная задача, в первую версию не идёт. |
| Составные буквы (Ё, Й, i, j, знаки препинания) распадаются | 4 | Эвристика склейки плюс обязательные ручные «объединить» и «разделить». Автоматике доверять нельзя. |
| Базовая линия и высоты из картинки не выводятся | 6 | Не угадываем: направляющие тянет пользователь. |
| Кернинг | — | Не делаем. Честно написать в интерфейсе, что пар в шрифте нет. |
| Шрифт с картинки ИИ повторяет реальный шрифт из обучающей выборки | 7 | Строка рядом с кнопкой скачивания: в США охраняется программа шрифта, а не контуры; в России и ЕС дизайн может охраняться. |

## 7. Стек и раскладка

Ваниль без сборщика, как в Charsets и MDEditor: ES-модули напрямую,
GitHub Pages, никакого сервера. Зависимости — три, все в `vendor/`.

- **opentype.js** — сборка `.otf` из глифов (этап 7).
- **JSZip** — пакет SVG и файл проекта (этап 8).

Трассировщик свой, поэтому сейчас зависимостей нет вообще.

```
Pantograph/
  index.html
  css/
  js/
    core/     path.js  geom.js  bezier.js  simplify.js  primitives.js
    prep/     crop.js  mask.js  symmetry.js
    trace/    trace.js
    glyphs/   segment.js  merge.js  build.js  assign.js  metrics.js
    editor/   ops.js  history.js  render.js  tools.js
    export/   svg.js  font.js  zip.js
    ui/       viewport.js  app.js  cropTool.js  params.js
              splitter.js  hints.js  guidesTool.js
    worker/   pipeline.js
    store.js  project.js  idb.js
  vendor/     opentype.js  jszip.js
  tests/      run.js  *.test.js  browser.html  *-visual.html
  SPEC.md  ARCHITECTURE.md  README.md
```

Тесты — на `core/`, `glyphs/segment` и `export/svg`: там чистые функции
и проверяемые ответы. Препроцесс и редактор проверяются глазами, автотесты
на них не окупятся.
