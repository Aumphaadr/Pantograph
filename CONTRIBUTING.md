# Правки и сообщения об ошибках

Самый полезный вклад в Пантограф — сообщение об ошибке: контур, который
ушёл от картинки, узлы там, где их не должно быть, кнопка, которая ведёт себя
не так. [Заведите issue](https://github.com/Aumphaadr/Pantograph/issues/new):
на каком шаге и с какими настройками, что сделали, что увидели и что ожидали
увидеть. Лучше всего приложить проект, сохранённый кнопкой «Выгрузить», — в этом
zip лежат и картинка, и настройки, и правки узлов, и ошибку можно повторить.

Правки принимаются на условиях лицензии проекта — [MIT](LICENSE).

## Где что лежит

- [SPEC.md](SPEC.md) — что делаем и в каком порядке, риски, отвергнутое.
- [ARCHITECTURE.md](ARCHITECTURE.md) — типы, пространства координат,
  инварианты, граница владения, уроки, купленные отладкой; раздел 11 —
  раскладка папок.
- [BACKLOG.md](BACKLOG.md) — сделанное с датами и отложенное с причинами.
- [CHANGELOG.md](CHANGELOG.md) — что изменилось для пользователя, по датам
  публикации.

## Как устроена правка

1. Счёт — чистые функции без DOM в `js/core`, `js/prep`, `js/trace`,
   `js/assemble`, `js/glyphs`, `js/export`; новая функция приходит вместе
   с проверками в `tests/*.test.js`. DOM — в `js/ui`, а кроме него только
   в показе контура (`js/editor/render.js`) и вырезке кропа холстом
   (`js/prep/crop.js`).
2. Настройка стоит рядом с тем, на что влияет: в панели того шага, где виден
   её результат. Новая настройка — строка в `CONTROLS` (`js/ui/params.js`)
   с подсказкой `hint`: кружок с вопросом есть у каждой, это проверяет
   `tests/params.test.js`.
3. Допуски — в пикселях исходника и соразмерны фигуре (README, «Принципы»).
4. Строка в [CHANGELOG.md](CHANGELOG.md) в разделе «Не опубликовано»,
   запись с датой в BACKLOG.md, урок или новый инвариант — в ARCHITECTURE.md.

## Проверка перед публикацией

- `npm test` заканчивается строкой «Пройдено N проверок», без строк «✗».
- `node tests/e2e.mjs` — сквозной прогон в headless-браузере: бросает картинку,
  тянет кроп, правит узлы и скачивает SVG. Без google-chrome или chromium
  прогон пропускается.
- Правка обводки — ещё мерные линейки `node tests/fontref.mjs`
  и `node tests/iconref.mjs`, до и после. Им нужна папка `refs/` с корпусами,
  которой в репозитории нет (см. [THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md),
  раздел «Мерные корпуса»); без неё линейки говорят, что сверять не с чем.
- Страница открыта через http-сервер (`npm run serve`), а не с диска:
  из-под `file://` ES-модули не грузятся.
- В консоли браузера нет ошибок; интерфейс проверен в светлой и тёмной теме.

## Правила

- **Статика без сборки и зависимостей.** JavaScript в ES-модулях, CSS и SVG,
  без CDN: всё, что нужно странице, лежит в репозитории. `npm test`
  не пропустит страницу, которая что-то грузит с других сайтов.
- **Тихое враньё недопустимо.** Качество меряется, а не угадывается; о том,
  что не взялось, интерфейс говорит словами.
- **Страж проверен на обратном.** Новая проверка должна падать, если сломать
  то, что она сторожит, — это проверяется руками один раз, до публикации.
- **Кегль в интерфейсе не ниже 14 px.** Иерархия держится насыщенностью,
  цветом и разрядкой.
- **Кнопка без подписи — значок из набора Klaarheid Icons**, а имя кнопки —
  в `aria-label`. Символы Юникода и эмодзи вместо значков не ставятся —
  ни на кнопки, ни в подписи настроек; кнопки сторожит `tests/icons.test.js`.

## Чужие файлы

Всё, что не создано для проекта, — библиотека, шрифт, картинка, набор
данных — добавляется, только если:

1. лицензия разрешает свободное использование, в том числе в образовательных
   организациях и коммерческих продуктах;
2. текст лицензии лежит рядом с файлом — как
   [`vendor/opentype.js-LICENSE.txt`](vendor/opentype.js-LICENSE.txt)
   у opentype.js (у библиотек в `vendor/` это проверяет `npm test`);
3. в [THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md) появилась строка: что это,
   откуда, кто автор, какая лицензия и где файл лежит.

Всё, что нужно странице, подключается своими файлами из репозитория — не с
чужих серверов, не через CDN и не прямыми ссылками на файлы репозиториев
GitHub и сайтов на GitHub Pages, в том числе набора Klaarheid: GitHub
не хостинг для раздачи файлов сайтам. `npm test` следит за этим сам: страж
`tests/local-only.test.js` не пропустит страницу, стиль, сценарий или значок,
который что-то грузит извне. Ссылка для перехода на другой сайт —
`<a href="https://…">` — загрузкой не считается.

Библиотеки кладутся файлами в `vendor/`, без изменений, с записью
в [`vendor/README.md`](vendor/README.md): версия и откуда взят файл.

Значки берутся из набора [Klaarheid Icons](https://aumphaadr.github.io/Klaarheid-Icons/)
(MIT-0) командой

```
npm run icons:sync -- <папка набора> <имя значка> …
```

Она копирует файлы из папки `svg/fill` локальной копии набора (`git clone`)
в `icons/klaarheid/` байт в байт, собирает из них `js/ui/icon-data.js`
и пересобирает раздел «Значки» в THIRD-PARTY-NOTICES.md. По сети команда
ничего не качает и адрес вместо папки не примет; страница берёт значки
из `icon-data.js`, а не с сайта набора. Без имён команда обновляет значки,
которые уже лежат в папке; чтобы убрать значок, удалите его файл и запустите
её снова. Руками не правятся ни файлы значков, ни `icon-data.js`, ни этот
раздел: обновлённый значок снова копируется из набора.

Мерные корпуса (`refs/`) и картинки для смотровых страниц (`icon-crops/`,
`icon-masters/`, `glyph-sheets/`) в репозиторий не кладутся — они закрыты
в `.gitignore`. Картинку для автотеста тест рисует сам, как `tests/e2e.mjs`.
